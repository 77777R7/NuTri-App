## 4. Stage C 详细执行步骤（按顺序）

## C0. 冻结 Stage C 基线（开工前）
目标：确保 C 阶段每次改动可与 B 阶段完成态对比。

产物：
1. `stage_c_baseline_manifest.json`
2. `stage_c_baseline_metrics.json`

至少包含：
1. 当前 git commit/branch
2. Stage B 通过产物路径
3. Stage C 品牌范围（30 品牌）
4. Stage C lane 范围（2 lanes）

## C1. 建 seed + 跑覆盖率统计（只读）
目标：把 Top30 品牌准确映射到你们真实 schema，并拿到 patch ROI 基线。

动作：
1. 导入 `target_brands_seed(market, brand, rank, patch_priority_score)`
2. 跑覆盖率与缺失分布统计（按 JSON SQL 模板映射真实表）

必出工件：
1. `brand_scope_products`
2. `brand_coverage_summary`
3. `brand_missing_field_distribution`
4. `brand_category_patch_candidates`

门禁：
1. 若品牌规范化命中率过低（例如 alias 问题），先补 brand normalization 映射，不进入 C2。

## C2. 构建 patch candidates（仅两条 lane）
目标：把“缺失且可修复”的 identity 变成候选队列。

动作：
1. 生成 `directions_text` 候选（DSLD 缺失 + label 证据）
2. 生成 fish oil breakdown 候选（缺 EPA/DHA/total + label 证据）
3. 输出 fixable/ceiling 归类

必出工件：
1. `stage_c_patch_candidates_directions.jsonl`
2. `stage_c_patch_candidates_fishoil.jsonl`
3. `stage_c_patch_candidates_summary.json`

## C3. conflict filter + review queue
目标：任何与 official_record 明确值冲突的候选，禁止自动写入。

规则（硬约束）：
1. raw_data_policy：只 overlay，不覆盖 raw LNHPD/DSLD
2. conflict_rule：冲突默认不写入，入 review queue
3. patch 必填字段：
   - `identityKey`
   - `fieldKey`
   - `patchedValue`
   - `sourceTier`
   - `evidenceRef`
   - `confidence`
   - `owner`
   - `status`
   - `expiresAt`
   - `reasonCode`

必出工件：
1. `stage_c_patch_conflicts_queue.jsonl`
2. `stage_c_patch_candidates_filtered.jsonl`

## C4. shadow apply（先影子，不落最终生效）
目标：先验证 patch 对 verdict 分布与稳定性的影响。

动作：
1. 在 shadow 模式应用 filtered candidates
2. 跑回放与对账（建议延续 stable -> s50 run1 -> s50 run2 -> killer10 -> reconcile）
3. 记录前后差分

必须观测：
1. directions 缺失率变化
2. fish oil active breakdown 缺失率变化
3. 冲突率
4. authoritativeExpectedButNotFinal 是否回归
5. digest/409/fallback 是否回归

## C5. enforce（仅通过门禁的 patch）
进入条件：
1. C4 指标通过
2. 冲突写入接近 0（或已全部进入 review queue）
3. 无稳定性回归

动作：
1. 仅对“高置信、无冲突、有证据链”的 patch 执行 enforce
2. 保留 owner/status/targetRelease 追踪

## C6. Stage C 验收与关闭
验收门禁（推荐硬化）：
1. `missing_directions_dsld` 在 Top30 范围显著下降（建议 >=20% 相对下降）
2. fish oil `missing_active_breakdown` 显著下降（建议 >=20% 相对下降）
3. conflict write rate 接近 0（建议 <=1%）
4. 不引入稳定性回归：
   - `authoritativeExpectedButNotFinalCount` 不上升
   - `doneSeenRate` 不下降
   - killer timeout 不上升
   - digest/409/fallback 继续满足 B2 阈值

关闭产物：
1. `stage_c_gate_report.json`
2. `stage_c_gate_report.md`
3. `stage_c_fixable_repair_queue.jsonl`
4. `stage_c_ceiling_explain_queue.jsonl`
5. `stage_c_release_note.md`
